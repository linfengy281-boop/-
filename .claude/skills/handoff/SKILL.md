# 交接档案（handoff）

目标：把当前对话里**只存在于上下文中**的信息全部落盘，新对话读完档案即可无缝继续，不需要用户重复解释。

## 触发
- `[handoff-watch]` hook 提示上下文 ≥ 60%（阈值可用环境变量 `HANDOFF_THRESHOLD` 调整，窗口大小用 `HANDOFF_CONTEXT_WINDOW`）。
- 用户手动说“交接 / 换对话 / /handoff”。可手动查用量：`python3 .claude/skills/handoff/scripts/context_usage.py <transcript路径>`。

## 步骤

1. **收尾当前小步**：不要在写文件改到一半时交接；先让代码处于可描述的状态。
2. **确定命名**：当前会话名 = 用户给的名字；没有则用项目目录名。运行
   `python3 .claude/skills/handoff/scripts/next_name.py "<当前会话名>"`
   输出 `原名 \t N \t 原名（交接N）`。例：`做登录页` → `做登录页（交接1）` → 下次 `做登录页（交接2）`。已带（交接K）的名字自动 +1，且会参考 `.claude/handoffs/` 里已有文件，不会重号。
3. **收集事实**（用工具核实，不凭记忆）：`git status`、`git diff --stat`、`git log --oneline -10`、当前分支、未跑/失败的测试、后台任务。
4. **写档案**到 `.claude/handoffs/<新名字>.md`，必须包含以下章节（没有内容写“无”，不要省略）：
   - **元信息**：新名字、上一份档案路径、日期、分支、上下文用量
   - **一句话目标 / 最终要达成什么**
   - **用户的原话要求与偏好**（尽量保留原话：风格、禁忌、语言、约定）
   - **已完成**（含改动的文件路径，`file:line`）
   - **进行中**（做到哪一步、卡在哪、下一个具体动作）
   - **待办**（按优先级排序）
   - **关键决策与理由**（含被否决的方案及原因，防止新对话重走弯路）
   - **踩过的坑 / 失败的尝试 / 报错原文**
   - **重要事实**（路径、命令、环境变量名、接口、账号类**不要写密钥**）
   - **待用户确认的问题**
   - **验证方式**（如何跑测试/启动，当前通过情况）
   - **新对话启动提示词**（见下）
5. **提交档案**：若用户的流程允许，把档案与未提交的工作一起 commit（云端会话容器会被回收，未推送即丢失）。不要擅自 push，除非任务本身要求。
6. **给用户的收尾消息**（简短）：
   - 档案路径与新名字；
   - 让用户**新开一个 Claude Code 对话，命名为 `<新名字>`**（用 `/rename <新名字>`），然后粘贴启动提示词。

## 新对话启动提示词（写进档案末尾，并在收尾消息里再贴一次）

```
这是「<新名字>」，接续上一个对话。请先完整阅读 .claude/handoffs/<新名字>.md，
再运行 git status 核对现状，用三句话复述目标、当前进度和下一步，等我确认后继续，不要重做已完成的部分。
```

## 新对话里的行为（接手方）
- 先读档案，再用 git 核对档案与现状是否一致，有出入以现状为准并指出。
- 档案里“待用户确认的问题”先问再动手。
- 本对话到 60% 时同样走本流程，名字自动变为（交接N+1）。

## 注意
- 档案要**详细但可扫读**：用清单和路径，不要贴大段代码（给 `file:line` 即可）。
- 永远不要写入密钥、token、个人隐私。
- 未经核实的内容标注“未验证”。
